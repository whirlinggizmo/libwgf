Build the game in `{DIR}/spec.md` in Haxe, using **libwgf**.

- **How libwgf looks here.** libwgf is a C library for games, and this is its Haxe binding, package `wgf`: `import wgf.*;` brings it in. Each kind of handle is a class (`Actor`, `Model`, `Texture`, `Sound`), with the calls on it as its methods; each header's other calls are a class's static functions (`Window.setTitle`, `Keyboard.isDown`), and its enums are enums of the same names. `{DIR}` is a game made by libwgf's `wgf new`: `wgf.json` says what it is, and `src/Main.hx` is the template's program, to replace.
- **Docs:** the binding's API is in `{DIR}/docs/api/`, a file a class with each call's doc comment; `docs/api/README.md` is the binding's README and `docs/api/BINDINGS.md` how it maps libwgf's C. libwgf's C examples are in `{DIR}/docs/examples/`. Read them as you need. Read nothing else about the library: no library sources, no other documentation, no web. Where you get the API wrong, the compiler tells you.
- **Shaders:** a shader of your own is packed by libwgf's tool, as `docs/api/Shader.hx` says: libwgf's staged files are in `{SHARE}`, its `shaders/wgf.glsl` (what a shader is given) and `tools/pack_shader.py` (`python3 {SHARE}/tools/pack_shader.py name.glsl -o assets/name.wgfshader`).
- **Assets:** the game's files are in `{DIR}/assets/`. The template's `Asset.setHost("assets")` makes that folder the program's, so it names them by their paths from it, as `"characters/Adventurer_Body.glb"`.
- **Building:** in `{DIR}`, `wgf build --desktop` builds the program natively as `build/desktop/{NAME}`. You may add to `wgf.json`. Build as often as you like.
- **Running:** `./build/desktop/{NAME} [arguments]` from `{DIR}` runs it, passing it the arguments (as `--enemies=50 --seed=1`). It runs on a display of its own, never on the desktop, with no sound. The program must exit on its own, as your shell waits for it, so give it a way to stop (an argument naming the frames to run, say). To see the game, save screenshots with libwgf's call for it and look at them. Run it in the foreground: a program left running in the background keeps your session from ending.
- **Touch:** the display here has no touch screen, so the touch controls can't be tried. Write them as the spec says.
- **Writing:** write to `{DIR}` only: the game's `.hx` files (`src/Main.hx` and what it imports), its shaders, and `wgf.json`, then `NOTES.md` with each compile error you hit, in order, and what you changed for it; each place libwgf's API had no call for what the spec asks and what you did instead; each place you were left guessing and what you guessed; and anything you expect not to work.
- **Budget:** stop at 3 hours or when the spec is met, whichever comes first, and reply with one line saying which.
