# wgf: libwgf for Haxe

Games in Haxe on libwgf: on the web, Haxe's JS against libwgf's prebuilt wasm host; on the desktop, hxcpp linking libwgf's staged archive. The API is generated from libwgf's headers, one member per C call; how it maps them is [docs/BINDINGS.md](../../docs/BINDINGS.md).

```haxe
import wgf.*;

class Game {
	static var world:Canvas;
	static var ship:Shape2d;

	static function main() {
		Runtime.run(init, null, frame, null);
	}

	static function init() {
		world = Canvas.create();
		ship = Shape2d.create();
		ship.setPolygon([16.0, 0, -12, -10, -12, 10]);
		ship.setParent(world);
	}

	static function frame() {
		ship.setRotation(0, 0, Time.getSeconds());
		world.draw();
	}
}
```

## Using it

- **Install:** `haxelib dev wgf <libwgf>/bindings/haxe` (or `haxelib git wgf https://github.com/whirlinggizmo/libwgf main bindings/haxe`).
- **The web:** `haxe -lib wgf --main Game --js game.js -D js-es=6 -dce full`, beside a host (`tools/build_host.py`, which writes `wgf-host.js` and `.wasm`, and the JS binding, `wgf.js`, beside them) and a page from `hosts/web/page.html`. The page makes the host, attaches the JS binding to it, and loads the program, which finds the binding at `globalThis.wgfJs`: every call the program makes goes through it ([the JS binding](../js/README.md)).
- **The desktop:** `haxe -lib wgf --main Game --cpp build -D HXCPP_M64 -D wgf_out=<libwgf>/out/<platform>/<variant>`, against a variant staged by `tools/stage_variant.py` and built by the toolchain hxcpp uses (the MSVC presets for MSVC). Add `-D wgf_headless` for a headless variant.
- **Behaviors:** a class extending `wgf.Behavior`, registered by its behavior's name (`Behavior.register("Rock", Rock.new)`), is made for each entity with that behavior, told of its triggers, and ended with it.

## What's here

- `src/wgf/*.hx`, except the files below: the API, generated by `tools/gen_binding.py` (each says so at its top; edit the headers or the generator, never them).
- `src/wgf/impl/Raw.js.hx`, `Raw.cpp.hx`, `BuiltVersion.hx`: the C calls for each target (on JS, the JS binding's), and the version the binding was made from, generated too.
- `src/wgf/Runtime.hx`, `Behavior.hx`, `Vec2.hx`, `Vec3.hx`, `Vec4.hx`, `impl/Host.js.hx`, `impl/Host.cpp.hx`: the runtime, written by hand.
- `project/Build.xml`: hxcpp's link of the staged archive.
- `test/`: the binding's test, run by `tools/check_binding.py` on hxcpp, under node, and in a browser.

Tested with Haxe 4.3.7 and hxcpp 4.3.2. `haxelib.json` lists no dependency: hxcpp is the native toolchain, as Haxe is, and is named here rather than pinned.
